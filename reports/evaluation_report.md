# Evaluation Report

Automotive Vision Defect Detection + Active Learning -- all numbers below are read directly from `reports/metrics/*.json`, generated by the scripts named in each section. None are hand-entered; anything not yet run is stated as such rather than estimated.

## 1. Objective

Evaluate whether an industrial visual-inspection pipeline combining a classical CV baseline, a supervised classifier, a patch-based anomaly detector, calibrated uncertainty estimation, and active-learning sample selection can (a) detect surface defects reliably and (b) reduce the amount of labeled data required to do so, using automotive hardware inspection (metal fasteners) as the target application domain.

## 2. Dataset and Protocol

**MVTec AD `metal_nut`** (335 real images: 220 normal + 115 test = 22 good + 93 anomalous across `bent`/`color`/`flip`/`scratch`, each anomalous image with a pixel-level ground-truth mask). Not automotive production data -- the closest available analog to a fastener/hardware inspection target in this benchmark. See `data/README.md` for full provenance and license (CC BY-NC-SA 4.0).

**Two distinct protocols are used, and are not interchangeable:**

1. **Anomaly detection** -- MVTec's official protocol: train on 220 normal-only images, evaluate on the full 115-image test set.
2. **Supervised classification + active learning** -- these need labeled *defective* examples, which only exist in the 115-image test folder. This project carves its own stratified split of that pool: 64 train + 16 validation (both drawn from a development pool) and a separate 35-image held-out test set never touched during training or model selection. This is a deliberate deviation from protocol 1, not an oversight.

## 4. Classical Baseline

Grayscale intensity histogram + LBP texture histogram + Sobel edge-magnitude histogram per whole image, scored by nearest-neighbor distance to a bank of normal-image feature vectors. Deliberately simple -- a reference point, not a competitive method.

- Image AUROC: **0.577** (95% CI: [0.456, 0.698])
- Image AUPRC: **0.872** (95% CI: [0.793, 0.931])
- Inference: 45.8 ms/image

AUROC barely above chance (0.5), as expected for whole-image texture statistics with no spatial localization -- this is the intended role of this baseline.

## 5. Anomaly Detector (PatchCore-lite)

A **simplified PatchCore-style** detector: frozen ResNet18 mid-level (layer2+layer3) patch embeddings, a memory bank of normal-image patches, nearest-neighbor (k=1) distance as the anomaly score. Simplified relative to the original paper (Roth et al., 2022) in two ways: (1) uniform random memory-bank subsampling instead of greedy minimax coreset selection, and (2) single nearest-neighbor instead of k-NN re-weighting. This is a portfolio reference implementation, not a reproduction of the paper's benchmark numbers.

- Image AUROC: **0.944** (95% CI: [0.894, 0.981])
- Image AUPRC: **0.987** (95% CI: [0.974, 0.996])
- Pixel AUROC: **0.953** (over 5,770,240 pixels, 676,274 positive)
- Memory bank: 10,000 patches, built in 5.4s
- Inference: 31.5 ms/image on mps

See `reports/figures/anomaly_roc.png` (ROC vs. classical baseline) and `reports/figures/anomaly_heatmap_examples.png` (localization on real `bent` defects).

## 6. Supervised Classifier

Partial fine-tune ResNet18 (layer4 + classification head unfrozen; layer1-3 frozen at ImageNet weights), chosen over a larger backbone specifically because the labeled pool is tiny (~80 training images across 5 classes) -- a bigger model would only add overfitting risk. Class-weighted cross-entropy, early stopping and LR scheduling on validation macro-F1.

- Held-out test (n=35): accuracy **0.800**, macro-F1 **0.794**
- Best epoch: 7 of 16 run (early-stopped)

| flip | 1.000 | 1.000 | 1.000 | 7 |

## 7. Uncertainty Estimation

Every classifier prediction carries three softmax-derived signals (`src/automotive_vision/models/uncertainty.py`): **confidence** (top-1 probability), **normalized entropy** (0-1, comparable across class counts), and **margin** (top-1 minus top-2 probability). A prediction is routed to human review when confidence falls below a configurable threshold (and optionally when entropy exceeds one). Monte Carlo dropout is also implemented (`mc_dropout_predict`) as a second, independent uncertainty signal, but is not wired into the default inference path -- available for future comparison, not part of the reported results below.

## 8. Calibration

Temperature scaling was fit on the 16-image validation set and evaluated for Expected Calibration Error (ECE) on the 35-image held-out test set.

| | ECE |
|---|---:|
| Raw | 0.115 |
| Temperature-scaled (T=0.143) | 0.179 |

**Interpretation, scoped to this experiment:** temperature scaling made calibration worse here rather than better. The most likely explanation is that fitting a single scalar temperature on only 16 validation examples is unstable -- the fitted value overfit that small sample and over-sharpened confidence on the held-out test set. This is a known risk of temperature scaling under small validation sets in general, but the specific causal claim here is an interpretation of this one run, not a universal result.

The human-review confidence threshold (0.7, see `configs/inference.yaml`) was chosen by this explicit rule, not asserted as optimal: *smallest threshold with auto-decided accuracy >= 0.9 on held-out test (n=35); falls back to 0.7 if none qualify*. Full threshold sweep in `reports/metrics/calibration.json`; reliability diagrams in `reports/figures/reliability_diagram.png`.

## 9. Active Learning

**This is a simulation**, not a live annotation study: MVTec's ground-truth labels stand in for a human reviewer, revealed only when the acquisition strategy selects that sample. For compute reasons (4 strategies x 5 seeds x 8 retraining rounds), this uses frozen ResNet18 embeddings + a lightweight logistic-regression head rather than fine-tuning the full CNN each round -- the headline classifier numbers in Section 6 come from the fully fine-tuned model, not this lightweight head.

Pool: 80 images, held-out test: 35 (same held-out set as Section 6), 5 seeds per strategy.

| Strategy | Final macro-F1 (mean +/- std, full pool labeled) |
|---|---:|
| random | 0.627 +/- 0.000 |
| uncertainty | 0.622 +/- 0.010 |
| diversity | 0.627 +/- 0.000 |
| hybrid | 0.627 +/- 0.000 |

**Honest reading of this result:** uncertainty sampling shows the well-known "cold-start" pathology (worse than random early on), and all strategies converge once the full pool is labeled -- an expected sanity check, not a finding. Confidence bands (+/-1 std over 5 seeds, see `reports/figures/active_learning_curves.png`) overlap for most of the labeling-budget range. **This experiment does not demonstrate a statistically clear labeling-efficiency advantage for any acquisition strategy over random selection**, given the dataset's small size. A larger pool would be needed to resolve whether the mid-budget separation visible in the plot is signal or noise.

## 11. Error Analysis

Largest off-diagonal confusions in the held-out test confusion matrix:

- 3x true `bent` predicted as `color`
- 2x true `scratch` predicted as `bent`
- 1x true `good` predicted as `color`
- 1x true `bent` predicted as `good`

Weakest class: `bent` (F1=0.500). Strongest: `flip` (F1=1.000). With only 7 held-out examples per class, single misclassifications move F1 by ~0.14-0.29 -- these per-class numbers are indicative, not statistically precise.

## 12. Limitations

- Benchmark data (MVTec AD `metal_nut`) is not automotive production data.
- Human labeling in the active-learning experiment is simulated using ground-truth labels, not a live annotation workflow.
- Both the supervised and active-learning tracks train on a very small pool (up to 80 labeled images across 5 classes), because MVTec AD only labels defect subtypes in its test folder -- reported metrics (and their wide confidence intervals) reflect that.
- Active learning does not demonstrate a clear labeling-efficiency win in this experiment.
- Temperature scaling overfit its 16-example validation set and worsened calibration here, not universally.
- PatchCore-lite is a simplified variant (random coreset subsampling, k=1 nearest neighbor), not a reproduction of the original paper's method or benchmark numbers.
- Grad-CAM / anomaly heatmaps are correlational visualizations, not causal proof that highlighted pixels are the actual defect.
- Anomaly detection quality depends entirely on how representative the "normal" training images are; a shift in the true normal distribution would degrade it without warning.

## 14. Conclusions

**What was experimentally measured:** the anomaly detector clearly outperforms the classical baseline (0.94 vs. 0.58 image AUROC); the supervised classifier reaches 0.80 accuracy on a small held-out test set.

**What was simulated:** the active-learning human-labeling loop (ground-truth labels standing in for a reviewer).

**What came back negative or inconclusive, and is reported as such:** temperature scaling did not improve calibration here, and no active-learning acquisition strategy showed a statistically clear advantage over random sampling.

**What remains future work:** extending to a second MVTec category (`screw`), periodic full-CNN fine-tuning in the active-learning loop once more labeled data is available, cross-validated temperature fitting, and evaluating MC-dropout as a second review-routing signal.
